# 0851 — Original supplier debit and capitalized receipt return

Status: accepted engineering decision for an experimental PostgreSQL slice.
Date: 2026-10-10.

An original supplier receipt and its accrued payable cannot be corrected by an unrelated inventory reversal or generic journal. `SR1-` identifies a native source owner that commits the existing full receipt reversal, opposite original AP accrual, supplier credit and any paid landed-cost expense together. Existing FIFO, AP, financial posting, audit and outbox remain the sole operational and financial engines.

The initial contract selects one complete, unissued multiline receipt and its exact matching single-line, accrued, unpaid zero-tax AP invoice. The selected purchase line has one completed receipt and one complete invoice; other original purchase lines may remain and be settled normally. Budget-backed BPC1 purchases, issued inventory, already paid or partly paid invoices, partial receipt returns, FX and tax-bearing corrections are refused. Their appropriation, consumption, refund and tax lineage require separate contracts.

Public evidence retains the entire original native purchase header. Current amount authority therefore covers the larger of its original total and the correction's 2C financial burden, using the original retained precision. This applies before preparing drafts, after lock waits, to reads and to retained response retries. The payload financial amount remains exactly 2C; an authorization ceiling never changes accounting turnover. A narrowed policy that permits a small selected correction cannot expose a larger original purchase through the return endpoint.

Let B be original merchandise cost and C its original capitalized FIFO cost. The native inventory inverse debits receipt clearing C and credits inventory C. The AP inverse debits AP B and credits receipt clearing B. When C exceeds B, an existing governed manual entry debits a selected expense account C−B and credits receipt clearing C−B. Thus inventory removal, supplier credit and expense conserve the original cost exactly. Already paid freight and duties stay in original cash history; the return creates no cash refund. Current amount authorization uses the retained precision and complete financial burden 2C, with C bounded by 4.5×10^18 minor units.

Prepare locks corrective period SHARE, purchase parent, supplier and AP invoice; native receipt admission captures the canonical currency binding before FIFO locks. Review and post use the same ordering. Permission, selected scope, current persisted hierarchy grants and privileged-session assurance are checked again after parent waits and before returning a cached command receipt. Three distinct persisted humans prepare, review and post. Independent cancellation at phase 0 or 1 clears outstanding source claims but retains the original inverse drafts, review, command acknowledgements and evidence.

Four forced-RLS owner and credit tables bind exact native source snapshots, original immutable posting effects, original quantity and value, native reversal and GL outcomes, actor events, audit/outbox and command responses. Deferred invoker closure rejects direct SQL publication of only an AP credit or FIFO inverse. Finance reverse dispatch also routes any entry or effect that reverses an original native AP accrual back to its source owner, even when its new number is an unrelated Generated namespace. Ordinary native sources return before querying protected SR1 tables; retained owned sources fail closed when owner evidence cannot be read.

AP gains the additive terminal `Credited` status plus an immutable original/inverse credit link. Procurement quantities and original received/accrued totals remain historical; current projections expose credited, paid and outstanding amounts with original = credited + paid + outstanding. A successful return does not release original purchase quantity for automatic rereceiving. Cancellation releases only the pending return claim. Public native inverse preparation refuses SR1 entries and permits only the exact private source participant.

Studio verifies a canonical sealed plan digest while preserving monetary integer tokens above JavaScript's safe range. Lifecycle acknowledgements update visible evidence immediately and merge monotonically with already observed later phases. Lost responses retain the same scoped command for retry; every retry still requires current server authority. The initial list exposes the newest 25 retained return owners for one existing purchase; the direct ID route retains older inspection access.

Migration 0130 installs additive native columns and wrappers without rewriting old migrations. Empty rollback restores exact prior verifier bodies and removes empty owner tables; deployment bootstrap must restore recreated-table app ACL. Any retained owner, including a cancelled draft, refuses downgrade. Populated recovery uses forward correction or verified pre-upgrade restore.

Mandatory acceptance covers native SQL/API/actual HTTPS Studio, independent integer and GL oracles, paid landed-cost disposition, three-person separation, raw SQL attacks, current-authority replay refusal, lost-response retry, injected rollback after FIFO publication, true `pg_blocking_pids` receipt/AP-payment overlaps, restricted ordinary roles, ordered empty/populated migration and populated restore. Developmental cases do not establish final clean-source acceptance or a scale claim.
