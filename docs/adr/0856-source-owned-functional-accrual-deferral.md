# Source-owned functional-currency voucher schedules

Status: accepted implementation contract for the separate M2 slice; native execution pending.

AD1 owns an immutable reviewed source voucher or estimate and explicit fiscal-period tranches. It uses the existing Finance Core GL, period lock/reopen governance, monetary registry binding, review/post transaction and native audit/outbox. Allocation delegates to the existing exact integer Hamilton allocator, with stable tranche IDs as the tie break. The captured currency policy remains `ROUND_HALF_UP`; allocation is separately versioned as `native-hamilton-stable-id-v1`.

Four source modes remain explicit. A new prepaid voucher posts Dr Prepaid / Cr Cash once. Attachment of an exact paid expense posts Dr Prepaid / Cr Expense with the original expense dimensions and preserves the original cash effect. Attachment of an exact prepaid voucher records reviewed external original membership without inventing an additional GL effect. An expense-accrual estimate has no up-front cash effect; each approved tranche posts Dr Expense / Cr Accrued Liability and retains a later explicit reversal date and fiscal period. Only exact ordinary two-line original paid vouchers with retained native three-human provenance are eligible for attachment; another operating source, complex allocation or foreign currency needs its own qualified source owner.

The source voucher approval and each financial tranche require separate current preparer, reviewer and poster identities. Exact inverse tranches additionally require current `finance_core.reverse`. A reversal releases the exact tranche claim only after its native inverse posts, allowing one reviewed replacement. Original journals, captured policy, account mappings, dimensions, allocation weights and approved native snapshots cannot be edited.

Whole-original attachment uses the existing `financial_effect_claim_gates` and `financial_effect_ownership_guards/releases` directory. Revision `0141_pg_accrual_deferral` follows 140 and adds the AD1 namespace and exact owner closure after its owned tables exist. AD1 and active ME2 claims are mutually exclusive under the same serialized original-effect gate, including repeatable-read writers. Original entry/effect bytes receive no new prefix or metadata mutation. Cancellation may release an attachment before any financial consumption. Consumed attachment cannot admit generic original reversal; complete source correction is outside this first contract.

Schedule allocation and planned fixtures alone prove arithmetic, not ERP execution. Acceptance additionally requires actual PostgreSQL non-owner/FORCE RLS SQL closure, authenticated API source creation and three-person phases, current permissions and period locks after waits, races and rollback, populated migration/restore, original-effect export with a stdlib independent oracle, and real Arabic/English Studio execution. Local comparative performance remains deferred. SQLite availability must be explicit; there is no Community parity claim until an adapter is independently executed.

This is a bounded functional-currency management accrual/deferral source. It does not qualify country tax, statutory payroll, comprehensive IFRS/US GAAP reporting, AP invoice settlement, bank payment execution or a complete ERP. The separate IC2 cashflow view will classify actual paired-trade settlement membership: a USD3000 receivable settlement and USD3000 payable settlement net to zero, while closing translation of the retained cash contributes USD101 exchange effect. That exchange effect cannot be relabeled as settlement cashflow.
