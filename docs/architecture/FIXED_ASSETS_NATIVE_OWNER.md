# Source-owned fixed assets

FA1 composes the existing native Finance Core draft, independent validation and Finance Posting publication. It creates no ledger or currency registry. Each acquisition atomically retains an immutable asset definition and its complete native acquisition draft. Depreciation and disposal each retain a new source plan, its exact previous asset basis and a new native draft. One pending operation per asset and a locked asset definition serialize concurrent lifecycle commands.

The policy uses functional currency and six distinct existing chart accounts: historical cost, accumulated depreciation, depreciation expense, cash, disposal gain and disposal loss. Acquisition debits historical cost and credits cash. Depreciation recognizes the difference between rounded cumulative entitlement and previously posted depreciation. Cumulative entitlement is `ROUND_HALF_UP((cost - salvage) * completed_months / useful_life_months)` evaluated using exact integer arithmetic. The useful life is one to 1200 service months. A service month counts only after its final day; the first in-service month counts as one complete service month. This explicit convention does not claim statutory day proration.

Disposal debits proceeds and releases all recorded accumulated depreciation, credits original historical cost and recognizes the exact residual gain or loss. An asset with zero carrying value still has positive native disposal turnover; authorization evaluates its full debit turnover. Posted sources retain all original arithmetic, human identity, currency policy, native snapshot and evidence. Financial reports therefore consume the same native effects as other operations.

Every financial plan requires three distinct currently authorized, persisted humans. Preparation, review and posting use the central scope and ABAC policy. Native publication requires the connection-bound `_AssetPostingParticipant`; public generic publication and reversal cannot detach a reserved FA1 entry. Only reviewed asset-owned lifecycle commands may create effects. SQL deferred closure repeats the arithmetic independently, matches every ordered native GL line, binds all three identities and requires the exact audit/outbox evidence and retry acknowledgement. Asset definitions, reviews, links and commands are immutable; the only permitted plan mutation advances one phase. Forced RLS protects the complete tenant/workspace/organization/entity hierarchy.

Asset lists use a 25-row keyset page, with a configurable API maximum of 100. Financial history uses 25 retained plans per page and exposes earlier history. Scalar balances derive only from posted sources. Metadata changes cannot rewrite financial provenance. Populated downgrade refuses destruction of financial evidence. Native restore acceptance must transport the source tables, native finance tables, audit/outbox evidence, identity and master hierarchy, then verify the same independent balance equation and SQL refusal probes.

The completed contract is cash-funded acquisition, cumulative straight-line depreciation and disposal in functional currency. AP capitalization, tax, foreign currency, impairment, transfers, source cancellations and alternative depreciation methods require distinct future source contracts. No existing accepted engine is replaced.
