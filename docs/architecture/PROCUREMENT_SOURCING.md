# Retained sourcing over native appropriation owners

The source is one immutable, exact multiline demand in a canonical tenant/workspace/organization/entity. An approved native budget supplies currency precision and fiscal period. No sourcing stock, AP or GL ledger exists. Opening an RFQ, retaining supplier offers and reviewing the lowest complete exact offer create source evidence only. A third persisted human publishes the reviewed offer through the existing BPC purchase owner; its native purchase, Reserve event, source award and both owners' immutable acknowledgments commit in one transaction.

The lifecycle is `Draft -> OpenRFQ -> SelectionReviewed -> Awarded`. Draft, OpenRFQ and SelectionReviewed may be independently cancelled while retaining all original evidence. Each active scoped supplier has one immutable complete price vector. Selection orders by exact integer total and canonical supplier code; quote arrival time has no effect. The selected offer must fit the original ceiling and current available appropriation. Receiving, AP accrual/Consume and partial cash settlement then follow the existing native owners. Cancellation of sourcing cannot rewrite a published purchase or its effects.

The reserved purchase namespace is `BPC1-SRC5-`. Deferred closure on native purchases refuses an orphan even when a caller uses the existing budget purchase API or SQL instead of the sourcing route. Source closures reconstruct every historical acknowledgment and verify original quantity/price vectors, masters, offer seals, approver identities, native audit/outbox records and the selected native purchase. Four tables use FORCE RLS. SQL mutation guards lock live identities, roles and all three hierarchy grants; API and replay paths also enforce existing live session and original amount policies. Current read authority is required to disclose original evidence.

Award locking is scoped command advisory lock, original period SHARE lock, current native budget UPDATE lock, source UPDATE lock, then the existing native BPC owner. The source is reauthorized after locks. Losing an HTTP response keeps its exact prepared command, actor, expected version and idempotency key. Retry returns the immutable original acknowledgment; Studio obtains and verifies the current source and never regresses a newer source to that historical acknowledgment.

Optional manufacturing references call the actual ME1 requirement owner. Original `requirement_json`, digest, base item/unit, exact original quantity ceiling and nested canonical scope must agree. Reads and retries recheck current retained manufacturing source authority. Empty references have a guarded path that does not import or plan manufacturing tables, preserving ordinary procurement roles. These references describe original requirements, without calculating shortages or claiming MRP.

Studio receives monetary/scaled integers as decimal strings plus the exact canonical JSON retained by PostgreSQL. It verifies SHA-256 asynchronously and checks demand and quoted costs with BigInt. The browser test performs actual password/step-up authentication, budget approval, demand, RFQ, two offers, independent review and third-human award, then native partial receiving, payable consumption, two cash installments and unreceived release. The existing HTTPS driver supplies restricted-role backup/restore and direct SQL tamper probes.

The independent golden arithmetic is 10 EA at 1,200 plus 2.50 KG at 2,000 = 17,000. The losing offer is 18,000; the winner is 17,000. Receiving and invoicing 2 EA plus 2.50 KG equals 7,400. Cash installments 2,400 + 5,000 settle 7,400. Release of 9,600 leaves native budget available 12,600 from a 20,000 limit, retained inventory 7,400, and five native posting effects with debit and credit turnover each 22,200.

Initial native evidence is incremental: the first smoke exposed an ambiguous PostgreSQL JSON subtraction expression; its failure packet is retained. Parenthesizing the affected operators fixed the defect, and the actual full cycle passed with zero skips. This is not final frozen-source acceptance and supplies no performance improvement claim.

# Operations and rollback

Approve a native budget in Budget control, then create `SRC5-<number>` demand in Procurement sourcing using actual scoped masters. Another human opens the RFQ. Retain complete supplier offers, have an independent reviewer confirm the deterministic winner, and a third human publish the award. Open `BPC1-SRC5-<number>` in Partial procurement to submit and independently approve it, receive stock, match/AP accrue through appropriation consumption and pay through governed installments. Keep source digest, audit and outbox references with the native financial effect references.

An unconfirmed command remains pending and must be retried unchanged. A current authority/version refusal requires refreshing the source and reviewing current policy. There is no deletion or rewriting of retained offers or awarded history. Empty-table downgrade drops only the source extension and its owned hooks; populated downgrade refuses. Use forward correction or a verified pre-upgrade backup. Preserve all original budget/AP/FIFO/GL engines and application ACLs during upgrade and restore.

The slice is functional-currency, zero-tax and base-unit only, at most 128 lines and 32 retained suppliers. It does not admit budget-backed supplier returns, reinstatement or replacement receiving capacity. Those require native source-owned consumption reversal and original allocation conservation; no exclusion was silently relaxed. Weighted supplier scoring, split awards, portal integrations, net-shortage MRP, country tax compliance and production readiness are outside this accepted slice.
