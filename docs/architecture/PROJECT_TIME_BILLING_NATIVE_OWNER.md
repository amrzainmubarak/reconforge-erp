# Original project time, receivables and cash

PB1 composes approved public workforce time with existing native receivables and Finance Posting. It does not reinterpret private employment rates as customer prices. A separately prepared and independently approved effective Project price captures its customer, hierarchy, original native Project dimension/value and currency policy.

The pricing operation uses exact rational minute amounts and the canonical `Money.divide_exact` boundary. It rounds once per Project with the captured native policy, currently `ROUND_HALF_UP`. Wage accrual's separately captured `HALF_EVEN` earnings policy is not reused for invoicing. The first cycle requires the customer's currency to equal the legal entity's functional currency and records zero tax; no country tax pack is supported.

Each prepared bill creates the existing native AR invoice and submits it. Native revenue remains unposted. Review validates the original GL snapshot; a third current authorized human then approves the original AR invoice and publishes Dr AR / Cr Project revenue in the same transaction. Partial and final collection sources similarly publish existing native receipts/allocations with Dr Cash / Cr AR.

Nullable immutable `pb_owner_id` columns are added to native AR invoice and receipt headers. Existing rows remain NULL. An internal transaction selector assigns the composing source at INSERT, but grants no authority. Unique tenant-qualified deferred foreign keys and original source closure require exact qualified scope, native header, plan, effect, current actors, approved time and current customer controls. Ordinary legacy AR rows and native GL entries dispatch without reading protected billing tables; explicit regressions revoke every billing table privilege before exercising those old paths.

Billing claims are separate from payroll claims. Append-only claim/event records retain the original time digest. The single tenant-qualified head references an existing exact event sequence. Prepared claims become consumed only with posted original revenue. Unposted cancellation preserves the Submitted native AR and original history, appends Release, and makes the approved time eligible for a new bill. Posted consumed time is never released or silently reassigned.

Source-used native account identity is protected by three immutable account pins and composite foreign keys. Name and description metadata are outside the pinned tuple. This avoids SECURITY DEFINER functions or protected billing table lookups from ordinary native account mutation triggers. Public financial dispatch first identifies reserved old and new PB1/PB1C entry identifiers before any protected lookup, preserving both original-source rename refusal and ordinary legacy operations.

Reads require the current central policy and the existing locked persisted hierarchy/permission admission. Each emitted invoice uses its captured minor amount and precision; the page-level scope admission is insufficient by itself. Raw personnel names, employment rates and wage allocations are not part of billing evidence. Billing references public employee/time identifiers, commercial customer prices and authorized financial evidence.

The seven additive source tables use FORCE RLS and invoker functions with a fixed `pg_catalog` search path. Financial period locks precede currency binding and source composition. Exact command request/actor seals retain response-loss replay and refuse a changed original actor or request. Audit/outbox events record original source identity and digest. Ordinary worker delivery updates retain the immutable event tuple while the existing worker fencing checks remain authoritative.

The development native tests use the ordered140 schema plus the owned billing schema in a separate synthetic database. They do not establish central143, HTTP, a real TLS/browser cycle or release readiness. Those acceptance gates remain explicit. SQLite capability is unavailable rather than implemented through a second financial engine. Empty downgrade removes only the additive metadata; populated source history refuses destructive downgrade.
