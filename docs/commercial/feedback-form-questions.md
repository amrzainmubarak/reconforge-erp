# Feedback Form Questions

Use these questions for structured feedback from accountants, auditors, ERP consultants, finance controllers, workshop managers, stores managers, and operations teams.

## Background

1. What is your role?
2. Which industry or operating context do you work in?
3. Which ERP or accounting system do you use?
4. Are your relevant exports usually CSV, XLSX, PDF, saved search, or another format?

## Reconciliation Pain Points

5. Which reconciliation workflow is most painful today?
6. Where do spreadsheets still play a large role?
7. Which exceptions are hardest to explain or evidence?
8. Which month-end or audit tasks are most repetitive?

## Required Exports

9. Which stock, GL, inventory valuation, work-order, purchase, invoice, or item exports are available?
10. Which fields are essential for source-document traceability?
11. Are there fields that are frequently missing, renamed, or inconsistent?
12. Can sanitized headers be shared publicly?

## Audit And Control Issues

13. What are the biggest audit/control issues in stock-to-GL, WIP, spare parts, or work-order review?
14. Which exceptions should be considered high risk?
15. What evidence would make an exception easier to review?
16. What review notes or statuses are needed for follow-up?

## Local-First Approach

17. Is local processing important for your ERP exports?
18. What would make local processing safer or more acceptable?
19. What concerns would you have about generated reports and evidence folders?
20. Which files should never be shared externally?

## Evidence Binder

21. Does the evidence binder structure match how you would review exceptions?
22. What fields or files are missing?
23. Are checksums useful as an integrity aid?
24. What would make evidence easier for a reviewer to trust?

## Client Pack

25. Would a summary-only client pack be useful?
26. Which redaction options are necessary before external sharing?
27. What should the privacy note explain more clearly?
28. Which files would you expect to review manually before sending?

## Missing Features And Risks

29. What feature or workflow is missing for a safe pilot?
30. What objection would a finance, audit, IT, or data protection reviewer raise?
31. What would make the tool easier to evaluate using synthetic or anonymized data?
32. Are there documentation gaps that would block adoption?

## Pilot Interest

33. Would you be willing to test with synthetic or anonymized exports?
34. What would a successful pilot need to prove?
35. What timeline and scope would be realistic for a small pilot?
36. Would you prefer to give feedback through GitHub Issues, GitHub Discussions, email, or a short call?

## Privacy Reminder

Do not submit live ERP exports, credentials, customer names, employee names, supplier records, invoice values, GL accounts, or private financial information. Use sanitized headers, anonymized examples, or synthetic scenarios.
