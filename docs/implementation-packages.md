# Implementation Packages

These implementation packages are draft, non-contractual service outlines for evaluation planning. They are placeholders, not current customer claims, revenue claims, guaranteed deliverables, pricing commitments, or legal terms.

All packages preserve ReconForge's local-first, export-based model. They do not include SaaS hosting, direct ERP connectors, legal signatures, audit opinions, compliance certification, ROI promises, customer testimonials, or vendor-replacement claims.

## Package 1: Open-Source Self-Evaluation

Status: available as self-guided open-source workflow.

Suggested user:

- Technical evaluator.
- ERP consultant.
- Controller or internal audit reviewer with local Python support.

Draft scope:

- Install ReconForge locally.
- Run `doctor`.
- Run the standard demo.
- Run the synthetic enterprise demo.
- Review docs, security posture, and known limitations.
- Try one sanitized export-based sample or mapping profile.

Draft deliverables:

- Local generated demo outputs.
- Notes on setup friction.
- List of useful outputs and confusing areas.
- GitHub issues or discussions using synthetic/anonymized details only.

Draft pricing/terms:

- Open-source self-evaluation; no paid commitment implied.
- No support SLA unless separately agreed.

## Shared Data Handling Rules

- Use synthetic or anonymized data for public materials.
- Keep live customer data local unless the data owner approves a private support channel in writing.
- Do not place source exports, output packs, backups, or SQLite databases in git.
- Review generated evidence and client packs before sharing.
- Keep retention and deletion decisions in the pilot notes.

## Shared Claim Boundaries

- Pilot-ready open-source toolkit, not enterprise production readiness.
- Local evidence preparation support, not audit opinion.
- Checksum integrity aids, not legal signatures.
- Export-based workflows, not direct ERP connectors.
- Draft service package ideas, not current customer proof or commercial traction.
