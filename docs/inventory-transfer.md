# Governed original warehouse transfer (IT1)

IT1 is a bounded PostgreSQL ownership workflow for one untracked item moving between two internal warehouses in the same legal entity. It uses the existing Inventory Core Generated Transfer movement and the shared quantity custody coordinator. It creates no second inventory ledger, warehouse valuation layer or transfer GL posting.

An approved entity FIFO pool retains its original cost ownership. Every cited layer must close through an original `Receipt` IRP plan, independent review, committed link, inbound valuation line/document, original validated GL and posted effect. Complete originals retain captured currency policy and current remaining layer quantities/value, consumption history, and row version. The first accepted fixture is three EA at a complete original value of USD 36. Moving one EA cites that full source value; a USD 20 read cap cannot authorize the displayed USD 36 original.

The maker creates an immutable Draft source and one original native Draft. Draft creates no stock reservation. A different human reviews the complete current approved FIFO/GL pool and reserves the exact source-location quantity through one shared Core guard. A third human posts the original native movement. The same transaction releases the exact guard, updates terminal owner disposition, retains actual native posting audit/outbox, and writes the immutable command receipt. Deferred complete closure rejects detached releases, incomplete native effects or fabricated historical responses. Source and destination pool locks precede the source write lock; authority is read again after queued locks.

Cancellation preserves the original native Draft and releases any reviewed claim. A Posted source is corrected by a separate inverse child with swapped original locations and unchanged original quantity/base UOM. The child has its own maker, reviewer, poster, period/date, current capacity, complete cost snapshot and exact commands. Posting the child compensates physical stock without editing or voiding the original Posted movement. Destination consumption or reservation, an altered reviewed pool, closed period or current interpretation/authority change refuses the dependent command atomically.

The first scope admits actual IRP Receipt cost owners only. Non-IRP or manufacturing/quality cost owners require their own complete source contracts before expansion. A retained pending or committed full receipt inverse refuses new cost adoption; IT1 uses the same shared quantity pool gate as receipt inverse preparation. Existing receipt inverse restrictions, including retained outbound transfer history, remain intact.

Installation is ordered: owned `TABLES_SQL`, Root's finite 146 source-directory/native dispatcher extension, then owned `OWNER_SQL`. Shared guard namespaces are the closed set MSP1 and IT1. Core release inserts carry explicit IT1 namespace. Native reserved number/reference establishes relevance before private owner lookup. Root invokes `it1_native_admit(TEXT,JSONB,JSONB,TEXT)` with an explicit `inventory_movements:INSERT|UPDATE|DELETE` or `inventory_movement_lines:INSERT|UPDATE|DELETE` action. The owner permits only original header/line birth and third-human header posting; later line edits and every deletion/void refuse. Deferred native closure calls `it1_native_close(TEXT,TEXT)`; quantity closure delegates to `it1_core_claim_close(TEXT,TEXT)` and `it1_core_release_close(TEXT,TEXT)`.

The API has eight explicit routes under `/api/v1/inventory-transfer/transfers`, with exact decimal-text quantities and string projections for native minor/scaled values. Command ACKs retain original operation, actor, request/digest, source/version, captured scope and complete historical native response. A later authoritative source read may advance beyond an old ACK; replay returns that old owned receipt under fresh whole-value authority.

Initial qualification is development evidence: 29 focused domain/API tests and actual two restricted-role native cases passed on unchanged source at `output/it1-native-original-draft-v3`. Those native cases establish original IRP3EA/3600 cost custody, unchanged pooled FIFO/GL, native Draft, current source get/list, immutable same-command replay and owned empty/populated inverse behavior. Earlier source-qualified v1/v2 failures are retained. Full 146 review/post/child inverse, adversarial authority/concurrency/direct SQL/restore, independent stdlib original oracle and real bilingual Studio/API browser acceptance remain required before claiming the complete transfer cycle.

There is no performance or production acceptance claim. Equivalent SQLite native source custody is unavailable in this slice. Root owns migration, common API registration, permission catalog, navigation, native browser runner and CI integration.
