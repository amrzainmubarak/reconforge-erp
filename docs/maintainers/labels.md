# Recommended GitHub Labels

GitHub labels are not stored as ordinary repository files unless a label-sync tool is added. Use this list when configuring labels manually or when introducing a future label-sync workflow.

| Label | Purpose |
| --- | --- |
| `good first issue` | Small, well-scoped tasks suitable for new contributors |
| `help wanted` | Tasks where outside domain or engineering help is useful |
| `documentation` | Docs, examples, wording, and navigation |
| `security` | Security hardening, vulnerability handling, safe output review |
| `erp-profile` | Export-based ERP mapping profile requests or fixes |
| `rule-pack` | Rule/control pack requests, validation, or improvements |
| `pilot-feedback` | Feedback from pilots, demos, walkthroughs, or practitioner review |
| `testing` | Unit, integration, smoke, fixture, or regression tests |
| `deployment` | Packaging, installation, Docker, and environment concerns |
| `docker` | Docker-specific build/runtime/docs issues |
| `commercial-docs` | Pilot, onboarding, feedback, pricing, or support-program wording |
| `audit-workflow` | Evidence, review workflow, handoff, controls, and auditor-facing output |

Optional labels:

- `accessibility`
- `sample-data`
- `needs-triage`
- `blocked`
- `duplicate`
- `wontfix`
- `release`
