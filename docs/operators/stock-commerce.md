# Governed multi-line commercial orders

Stock commerce extends the accepted Stock Sales source owner. It introduces one immutable commercial header, ordered product/location lines and explicitly owned fulfillment tranches. Existing Stock Sales, FIFO, Inventory, AR, Operational Finance and GL execute each tranche; there is no second financial posting engine.

In Studio open Stock Sales, authenticate and select a workspace, organization and legal entity. Commercial orders appear above the retained single-item workflow. Create priced lines, selecting products with the paged item-code prefix catalog and a warehouse/location for each line. Submit the parent, then have an independent human approve its frozen terms. A line can contain any positive exact UOM quantity whose priced value is additive in currency minor units. An order supports 1000 lines; the sum remains within 9000000000000000000 minor units.

Create a partial tranche against an approved line remainder. A second human approves and reserves it. Prepare and independently review FIFO/COGS, then a third human posts the physical delivery and financial cost in the same transaction. Prepare, review and post its native AR invoice and revenue. Prepare, review and post its full invoice collection. Additional tranches consume the same line remainder and retain the original product, location, unit price, discount and monetary policy. The parent shows committed/delivered quantities and invoiced/collected minor units independently reproduced from its native children. A cancelled, financially undelivered tranche releases its commercial commitment and native reservation through the existing governed cancellation operation.

Partial deliveries, invoices and collections are at commercial-order level. A native invoice tranche is collected in full. Single-invoice partial receipts, customer returns, credit/refund inverses, tax, price lists and credit-risk controls remain outside this contract. FIFO valuation retains the accepted entity/item-wide layer ordering while physical stock and reservations remain location specific. Only one active frozen FIFO issue per entity/item is admitted; complete it before preparing another issue of that item.

Each command carries one immutable command ID, expected parent version, reason and exact scope. Lost acknowledgements must retry the unchanged prepared request. Mutations return a compact immutable acknowledgement with source and progress digests; read the parent to load its current conserved projection. Stale competing writes fail and roll back. Requests creating or changing native commercial children require the corresponding parent command, retained human audit and latest progress acknowledgement in the same transaction. Deferred SQL closure rejects direct child phase changes or an unowned `EC1.` child even when native SQL permissions are present.

The runtime role needs the accepted native Stock Sales participant grants plus SELECT/INSERT on `stock_commerce_orders`, `stock_commerce_lines`, `stock_commerce_tranches`, `stock_commerce_commands`, and UPDATE only on `stock_commerce_orders`. All four tables have FORCE RLS; the runtime remains a nonowner without BYPASSRLS. Existing Stock Sales writers need SELECT on the optional commercial relationship tables for their deferred admission checks. The server uses the existing `sales.*`, `inventory.*`, `receivables.*` and `finance_core.*` permissions and current persisted human scope/step-up checks. No default role is granted these capabilities.

Migration `0116_pg_stock_commerce` follows `0115_pg_financial_installments`. Downgrade is allowed only with empty commercial history. Retained documents require a preserved native database backup/restore rather than deleting commercial or financial history.
