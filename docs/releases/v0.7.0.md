# ReconForge ERP v0.7.0

ReconForge ERP v0.7.0 is a foundation-stage release for local-first, export-based pilot evaluation. It prepares the project for conservative local review after the platform backbone, finance workflow foundations, synthetic enterprise demo, pilot/support/buyer readiness package, website launch copy, and deployment smoke polish work.

This release strengthens self-hosted/local-capable foundations. It is not a hosted production service, not a direct ERP connector suite, not a compliance certification, not an audit opinion workflow, not a legal signature system, and not a replacement for ERP, GRC, audit, or enterprise close platforms.

## Highlights

- Local platform backbone foundations: SQLite database, audit events, local users/RBAC, workflow state machine, REST API foundation, Studio auth-required mode, DB import/export, and backup bridge.
- DB-backed finance controls platform foundations for accounts, close tasks, approvals metadata, evidence registry, journal controls, intercompany, control testing, matching, unified exceptions, and metrics.
- Studio DB pages and local API route foundations for selected account, close, exception, and metric workflows.
- Synthetic enterprise demo package for multi-entity, multi-period walkthroughs using generated synthetic data only.
- Pilot/support/buyer readiness package: support playbook, pilot onboarding checklist, buyer FAQ, draft implementation packages, release readiness checklist, support intake template, pilot success criteria template, and expanded security questionnaire.
- Conservative website and launch copy package with homepage, product page, demo page, GitHub launch, release announcement, social snippet, and claim-boundary drafts.
- Deployment smoke documentation for local quality gates, demos, DB/API/Studio checks, auth-required Studio startup, and Docker build/runtime verification commands.

## Local Smoke Commands

Core quality and security checks:

```bash
python -m ruff check .
python -m mypy reconforge
python -m pytest
python -m bandit -q -r reconforge
python -m reconforge.cli doctor
git diff --check
```

Local demo and platform-foundation smoke checks:

```bash
reconforge demo run --output output/demo
reconforge demo enterprise --output output/enterprise_demo
reconforge db init --db output/reconforge.db
reconforge api serve --db output/reconforge.db --host 127.0.0.1 --port 8765
reconforge studio --input examples/sample_data --output output/demo
reconforge studio --input examples/sample_data --output output/demo --db output/reconforge.db --require-auth
```

The API and Studio commands are long-running local server commands. For release verification, start them locally, confirm they bind to the expected localhost port or page, then stop them.

Docker verification depends on local Docker availability:

```bash
docker build -t reconforge-erp .
docker run --rm reconforge-erp reconforge doctor
docker run --rm -v ${PWD}/output:/app/output reconforge-erp reconforge demo run --output output/demo
```

Do not claim Docker runtime verification unless these commands pass in Docker Desktop, Docker Engine, or CI.

- foundation-stage
- local-first
- export-based
- pilot evaluation

- finance controls platform foundations
- synthetic enterprise demo

Do not claim:

- enterprise-ready

- certified or compliant status

- audit opinions

- real customer, adoption, testimonial, revenue, or ROI claims

## Known Limitations

- The project remains early-stage and should be evaluated in controlled local pilots.
- Core workflows are local-first and export-based.
- Docker runtime verification depends on Docker being available in the environment where verification is run.
- API and Studio foundations are local evaluation surfaces, not public internet deployment guidance.
- Evidence checksums are integrity aids only.
- Review and certification metadata are workflow metadata only.
