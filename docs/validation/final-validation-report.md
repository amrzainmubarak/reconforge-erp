## Known remaining release gates

- Hosted PostgreSQL/shared-schema persistence is not implemented. Master-data including fiscal periods, ledger-control, identity, close, outbox, evidence, reconciliation-result, and reconciliation-execution bounded contexts plus the bounded server API/worker profile consume the PostgreSQL/RLS boundary, but the rest of Finance Core, other domain repositories, external worker transport, cache, artifact transfer, and exports remain outside PostgreSQL; the server profile still requires database-per-tenant SQLite domain routing.
- Enterprise identity integration, centralized user lifecycle, broad WebAuthn recovery/authenticator interoperability, and deployment-wide worker/UI principal propagation are not implemented; the bounded API server profile now includes optional user-verified WebAuthn MFA and propagates verified principals through its current domain routes, while explicit local CLI compatibility remains local-only by design.
- A bounded in-process multi-worker reconciliation scheduler is implemented, but distributed queue workers are not. Evidence upload/verification can use the explicit S3 registry path, but malware scanning, retention/versioning enforcement, worker orchestration, authorized downloads, and restore/replication workflows remain unintegrated.
- A bounded local outbox worker runtime exists; distributed queue workers, external transport, tenant propagation, and worker observability remain unimplemented.
- Alembic covers the PostgreSQL tenant/RLS foundation, master-data, ledger-control, identity, close-control, outbox-delivery, evidence-registry, reconciliation-result, and reconciliation-execution bounded contexts; full domain migration parity and production upgrade/restore exercises remain open.
- The React Studio remains an experimental/read-only surface rather than the complete finance-operations UI described by the target state.
- The connector SDK, full workflow/close expansion, broad control-pack library, and full API/CLI contract surface remain roadmap work.
- AP accounting/posting, statutory tax/withholding, payment execution, credit notes, and ERP writeback remain unimplemented; migration 15 is a governed workflow/matching foundation only.
- AR statutory posting, tax, credit notes, dunning/collections, payment execution, and ERP writeback remain unimplemented; migration 20 is a governed invoice/credit/receipt/aging foundation only.
- Docker runtime verification, security scanning, cross-platform CI, and million-row benchmarks require an environment with those services/tools available; no claim is made here that they passed.

## Interpretation

The repository is materially safer and more financially deterministic for local reconciliation/control workflows. The correct release posture remains foundation-stage local evaluation, as documented in the engineering audit and roadmap.
